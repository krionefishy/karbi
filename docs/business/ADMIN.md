# Админка

Раздел для того, что раньше делалось командами на сервере: сотрудники и боты уведомлений.

## Отдельный вход, общий бэкенд

Админка — не отдельное приложение. Тот же SPA и тот же API, но открывается только с
**поддомена**: на рабочем домене nginx отвечает `403` на весь админский префикс, а `/admin`
уводит редиректом. Фронтенд понимает, где он, по имени хоста, поэтому локально оба
интерфейса живут на одном адресе.

Права проверяются **в базе на каждый запрос**, а не по признаку в токене: access живёт
сутки, и снятие прав через токен догоняло бы человека к завтрашнему дню. Домен — второй
рубеж, а не замена этой проверке ([architecture/AUTH.md](../architecture/AUTH.md)).

## Сотрудники

Список: имя, активность, признак администратора, когда заведён и когда последний раз
входил.

| Действие | Что происходит |
| --- | --- |
| Завести | сервер генерирует пароль на 24 символа и показывает его один раз |
| Сбросить пароль | новый сгенерированный пароль, старый перестаёт работать |
| Заблокировать | вход закрывается; на рабочих маршрутах текущий токен доживёт до истечения |
| Выдать или снять админа | флаг в базе, действует со следующего запроса |

**Пароль генерирует сервер.** Форма, куда пароль вписывают руками, к концу недели содержит
`qwerty12`. Показанный пароль восстановить нельзя — только выдать новый; ответ с ним
помечен запретом кеширования, чтобы не осесть в прокси или истории браузера. Из алфавита
выброшены `0OoIl1`: пароль читают с экрана и перенабирают.

**Себя нельзя ни заблокировать, ни разжаловать.** Последний администратор иначе закрыл бы
раздел, который единственный умеет выдавать права. Если это всё же случилось (человек
уволился, флага нет ни у кого), выход — команда на сервере:

```
uv run python -m backend.commands.grant_admin --username ivanov
```

Свой пароль сотрудник меняет сам, зная текущий, — для этого админка не нужна.

## Боты уведомлений

Список ботов, регистрация нового и удаление. Регистрация просит код (по нему автоматизации
адресуют бота), заголовок и токен.

**Токен через сервер только проходит.** Он уезжает на релей, который его и хранит; здесь
не сохраняется ни в базе, ни в логах. Поэтому у приложения свой обработчик ошибок
валидации: стандартный вернул бы присланное значение обратно в теле ответа.

Порядок и смысл ответов:

| Ответ | Значит |
| --- | --- |
| бот создан | релей принял токен и вернул заголовок и шаблон ссылки-приглашения |
| токен отклонён | мессенджер сказал, что токен нерабочий; бот не записан нигде |
| сервис недоступен | релей не отвечает — проверить токен нечем, поэтому мы не гадаем |

Удаление снимает бота и здесь, и на релее: токен не должен пережить бота.

Подробности про подписки, приглашения и доставку — [NOTIFICATIONS.md](NOTIFICATIONS.md).

## Чего в админке нет

- **Журнала действий.** Кто снял права или удалил бота — в системе не записано.
- **Ролей внутри рабочего интерфейса.** Разделение только одно: администратор против
  сотрудника. Любой вошедший по-прежнему может всё с селлерами, включая безвозвратное
  удаление.
- **Управления подписками, очередью и расписаниями.** Подписки заводятся ссылкой-
  приглашением, расписания живут в конфигурации.
