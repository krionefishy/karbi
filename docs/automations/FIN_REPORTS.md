# Финансовые отчёты

## Зачем

Финансист каждую неделю сводит ОПиУ по всем кабинетам: выручка, комиссия, логистика,
реклама, удержания, себестоимость, маржа. Раньше цифры давал внешний сервис, а сводку по
шести кабинетам собирали руками — с копированием колонок и формулами, которые ломались.
Автоматизация считает то же самое из отчётов реализации WB и начислений Ozon и отдаёт
сводку готовой. Отчёт нужен к вечеру вторника; WB выкладывает отчёт за неделю в понедельник.

## Что собираем

Своего сбора нет. Деньги лежат в зеркале `wb_core` ([WORKERS.md](../architecture/WORKERS.md)):
шапки недельных отчётов реализации WB с итогами и строки детализации, а для Ozon — начисления
по дням, развёрнутые в строки (продажа, доставка, услуга по товару, услуга кабинета). Своё у
модуля — только то, чего маркетплейсы не знают:

- **подключённые кабинеты**;
- **себестоимость артикула в кабинете** с датой начала действия. Ключ — кабинет и артикул:
  один артикул WB встречается у двух кабинетов с разной закупочной ценой.

Ловушки отчёта WB, на которые опирается расчёт:

- за неделю у кабинета **два отчёта** — основной и «по выкупам»; деньги недели — их сумма;
- **возврат приходит положительной строкой** с типом документа «Возврат», а в итогах WB его
  вычитает;
- **на границе месяца WB закрывает отчёт не всегда**: 31 августа 2026 пришёл отдельным
  отчётом, а неделя 27 июля – 2 августа — одним. Поэтому неделя — все отчёты одной
  ISO-недели, а месяц собирается по дате операции каждой строки (`rrDate`), а не по дате
  отчёта;
- удержания различаются **только названием**, к которому дописан номер документа:
  «Оказание услуг «WB Продвижение», документ №…».

## Как считаем

Строки и формулы повторяют отчёт, к которому привык финансист, и сверены с ним на живом
отчёте до копейки.

| Строка | Откуда |
| --- | --- |
| Реализация (до СПП) | цена продавца `retailPriceWithDisc` × количество, продажи минус возвраты |
| Реализация (после СПП) | `retailAmount`, продажи минус возвраты |
| К перечислению за товар | `forPay`, продажи минус возвраты |
| Плановая комиссия | к перечислению − реализация до СПП |
| Комиссия | к перечислению − реализация после СПП; плюс, когда WB доплачивает скидку из своих |
| Себестоимость | проданные минус возвращённые штуки × себестоимость артикула |
| Логистика, штрафы, хранение, приёмка, доплаты | одноимённые суммы строк |
| Внутренняя реклама | удержания «WB Продвижение» |
| Отзывы | удержания «Баллы за отзывы»: аванс минусом, возврат неиспользованного аванса плюсом |
| Лояльность | `cashbackAmount` и `cashbackCommissionChange` |
| Прочие удержания | все остальные удержания: «Джем», перенос карточек, утилизация и т.д. |
| Прямые расходы | сумма статей расходов |
| Валовая маржа | реализация после СПП + прямые расходы |

Кредит — справочная строка и в прямые расходы не входит: погашение займа не расход периода.
«Внешний маркетинг» всегда ноль — WB о нём не знает; строка оставлена, чтобы раскладка
совпадала с прежним отчётом.

**Себестоимость на дату.** Новая цена действует со дня загрузки файла и прошлые периоды не
меняет: сданные цифры не должны меняться задним числом. Период раньше самой первой загрузки
считается по ней же — иначе вся история до дня первой загрузки осталась бы без
себестоимости. Отчёт считается по цене, действовавшей на его последний день.

**Сборка раз в десять минут.** Отчёт WB неизменяем, поэтому воркер складывает его один
раз, когда зеркало дочитало строки: по артикулу, размеру, месяцу операции и виду операции.
Страница и выгрузка читают сотни готовых сумм, а не миллионы строк зеркала. Себестоимость
в суммы не входит: она меняется и применяется при чтении — правка цены не требует
пересборки. Версия правила сложения хранится на отчёте: сменилась — отчёты пересобираются.

### Ozon

Строки — как в листе «ОПиУ Озон» старого отчёта. Начисление Ozon несёт тип из справочника
начислений (`/v1/finance/accrual/types`, 135 типов); статья отчёта — по типу, что не названо,
идёт в «Дополнительные услуги». Выручка и вознаграждение — поля продажи. Сверено на неделе
21–27.09 с «Экономикой магазина» кабинета до рубля.

| Строка | Откуда |
| --- | --- |
| Реализация до СПП (с баллами) | `sale_amount` продажи — цена с баллами Ozon |
| Реализация после СПП (без баллов) | `sale_price` + `coinvestment` (программы партнёров) |
| инф: Баллы Ozon и программы партнёров | `bonus` + `coinvestment` |
| Себестоимость | штуки продажи × себестоимость SKU; возврат — продажа с минусом, себестоимость возвращается |
| Комиссия | `sale_commission` |
| Обработка и доставка | типы логистики: Logistic, LastMile, Pick-Up, Fulfillment, Drop-Off… |
| Возвраты и отмены | Cancellation, ClientReturn, ReturnFlowLogistic… |
| Внутренняя реклама | PayPerClick, Promotion, BrandShelf, PointsForReviews… |
| Внешний маркетинг | ExternalPromotion, LeadGeneration… |
| Дополнительные услуги | всё остальное |
| Компенсации и прочие начисления | Compensation, SetOff, RealizationReportCorrection… |
| Услуги ЕАЭС | трансграничные типы |
| Валовая маржа | реализация с баллами + прямые расходы |

Вознаграждение Ozon берётся с цены с баллами, поэтому маржа считается от неё, а не от
выручки без баллов. Период у Ozon — календарный: неделя — семь дней, месяц — месяц; день
до вчерашнего, которого в суммах ещё нет, делает период неполным. Реклама по SKU Ozon не
делит (Performance API — отдельная задача), она идёт в строку «(пусто)» листа по SKU.

## Что показываем

- **Wildberries или Ozon** — переключатель на странице; строки у каждого свои. В отчёте
  Ozon — только кабинеты с учёткой Ozon.
- **Недели или месяцы года** — строки ОПиУ сверху вниз, колонка на период и итог года;
  сумма по всем кабинетам или один кабинет.
- **Выбранный период по кабинетам** — та самая сводка, которую раньше собирали руками.
- **Артикулы без себестоимости** с их выручкой: пока список не пуст, себестоимость и маржа
  занижены по модулю.
- **Выгрузка в Excel**: период по кабинетам, недели, месяцы, за неделю — листы «По
  артикулам» и «Остатки» (у Ozon — «ЮНИТ Ozon»: деньги SKU из начислений, к перечислению,
  себестоимость, операционная прибыль), артикулы без себестоимости.

**«По артикулам»** — те же 150 колонок, что в старом отчёте, в том же порядке. Формулы
восстановлены по его цифрам: итог услуг WB — плановая комиссия плюс все удержания; налог —
ставка кабинета от реализации после СПП, копейки отбрасываются; к оплате — реализация после
СПП минус услуги после СПП; прибыль — к оплате без налога минус себестоимость. Доли прибыли
от убытка — нули, как там. Удержания по документу, а не по товару (реклама, отзывы, «Джем»),
собираются в строку «(пусто)». Реклама по артикулам — из зеркала рекламы `wb_core`:
списание кампании с типом оплаты (баланс, счёт, бонусы) делится между её артикулами по
доле статистики за те же дни; без статистики — поровну по составу кампании; кампания,
которой зеркало не знает, — в строку «(пусто)». «Инф: реклама из ВБ Продвижение» — статистика
по артикулу как есть. Чего нет: самовыкупов, раздач, утилизации, кредита, НДС — в старом отчёте
их вносили руками, колонки оставлены пустыми ради раскладки.

**«Остатки»** — остаток на складах WB, его себестоимость и цена по среднему чеку недели (без
продаж — по последнему известному), реализация до СПП в день и дней на распродажу. В старом
листе остаток шёл вдвое больше: он складывал строки складов вместе с итоговой строкой отчёта.

**Остаток «на последнюю неделю»** снимается воркером в понедельник после трёх по Москве из
зеркала остатков и хранится за закрытой неделей. Неделя без снимка (текущая или раньше первого
снимка) берёт остаток из зеркала на момент выгрузки, о чём лист предупреждает.

## Расписание

Зеркало читает список отчётов WB раз в полчаса и дочитывает строки новых; начисления Ozon
читает раз в три часа по дням до вчерашнего, последние три дня перечитывает. Воркер модуля
раз в десять минут складывает дочитанное — отчёты WB и дни Ozon (до 60 дней на кабинет за
проход); проход без нового — несколько коротких запросов на кабинет. Отчёт за прошлую неделю WB выкладывает в понедельник, на странице он появляется
в тот же день.

## Состояния и ошибки

- Период с пометкой **«неполный»** — отчёт WB за него у какого-то кабинета ещё не дочитан
  зеркалом или не сложен воркером.
  Денег этого отчёта в цифрах нет; досчитается сам.
- **«Отчёты WB не читаются»** / **«Начисления Ozon не читаются»** — у кабинета падает сбор
  зеркала (ключ без категории «Финансы», отозванный ключ). Прежние периоды на месте, новые
  не появятся, пока не починят.
- Отсутствие кабинета в колонках — он не подключён к автоматизации или в архиве.

## Уведомления

Нет.

## Настройки

Файл себестоимости загружается со страницы: Excel с шапкой «Кабинет», «АртикулВБ»,
«Артикул пост.», «Себес, руб» (для Ozon вместо «АртикулВБ» — «SKU»). Колонка «Проч.затр» и
остальные не читаются.

- **Кабинет** файла сопоставляется с селлером реестра по названию без «ИП» и инициалов:
  «Ип Саниев» и «ИП Саниев Д.Т.» — один кабинет. Сверяется название целиком, а не первое
  слово — иначе «ООО Бета» легла бы на «ООО Альфа». Кабинеты без пары перечисляются в ответе.
- **Дата «Действует с»** по умолчанию сегодняшняя. Дата в прошлом нужна для исправления
  ошибки: периоды до первой версии считаются по ней, и опечатку в первой загрузке иначе не
  убрать. Версия на ту же дату переписывается.
- Цена, совпавшая с действующей на эту дату, новую версию не создаёт — файл загружают
  целиком каждый месяц.
