# Остатки FBS по складам

## Зачем

Селлер проверяла кабинеты руками: открывала каждый склад продавца в WB и смотрела, где по
баркоду стоит остаток, а где ноль. Здесь та же таблица, что она вела в Excel: строка —
баркод, столбцы — склады кабинета, сгруппированные по фулфилментам и округам, в сводном
столбце группы — сумма, нули красные. Вкладка на кабинет и лист «Сравнение», где все
кабинеты друг под другом.

Таблица только читает WB. Перенос остатка между складами («поставить 50 туда, где ноль,
и списать с другого») — следующая итерация; модуль распределения FBS на заморозке.

## Что собираем

Раз в `poll_minutes` (по умолчанию час) и по кнопке «Обновить данные», по каждому
подключённому кабинету:

- **склады кабинета** — `GET /api/v3/warehouses`. Зеркало переписывается целиком: склад,
  ушедший из кабинета, уходит и из таблицы — показывать остаток на складе, которого нет,
  значит показывать вчерашний день;
- **остатки** — `POST /api/v3/stocks/{warehouseId}` по `skus` (баркодам) — только для
  складов, которые стоят в какой-то группе. У кабинета бывает полсотни DBS/EDBS-складов,
  их никто не смотрит, и опрашивать их — тратить бюджет WB впустую. Строки в ответе нет —
  на складе остаток не заводили; в таблице это ноль и хранится нулём, иначе «остатка нет»
  и «склад не спрашивали» неотличимы.

Название и артикул строки берутся из каталога `wb_core` по баркоду. Баркод, которого в
каталоге нет, всё равно спрашивается у WB — просто без подсказки, что это за товар.

Нагрузка: один запрос на склад в группе, до тысячи баркодов за запрос. Пять кабинетов по
~35 складов — около 180 запросов в час.

## Группы и столбцы

Группировка **её собственная**, не федеральные округа WB: «Наш склад» (свои склады 1–6),
«ФФ Стас» (все fulfast), СЗФО, ПФО (вместе с ООО ЦПР), ЮФО, УФО. Из данных WB такое не
выводится, поэтому группы настраиваются на кабинет во вкладке «Столбцы»: порядок групп,
состав и порядок складов внутри. Склад стоит в одной группе; склад без группы не
показывается. Привязка — по id склада, а не по имени: одно и то же имя у разных кабинетов
— разные склады (например, «ФФ Волгоград 3» у Яночкиной — объект 223, у Мунаевой — 165).

У группы есть вид: `own` — свои склады, `district` — округ, `fulfilment` — фулфилмент. Вид
нужен листу «Сравнение»: там «Наш склад» раскрыт по складам, округа стоят суммами,
фулфилмент не показывается — так в её примере.

Первичное наполнение по её файлу делает команда
`python -m backend.commands.import_fbs_stock_board Пример.xlsx --apply`: лист → кабинет по
имени, столбцы → склады по имени из зеркала, группы → по «плюсикам» файла, баркоды → из
колонки B. Порядок групп при импорте переставляется по ТЗ: свои, ФФ, округа.

## Строки

Список баркодов ведёт селлер сама: вписала — остаток подтянется ближайшим обновлением (после
добавления обновление ставится в очередь сразу). Автоматически строки не добавляются:
таблица показывает то, за чем она следит, а не весь каталог. К строке есть свободная
заметка («стоит в 1С», «дубль карточки») — колонка A её таблицы.

## Что показываем

Страница кабинета: заметка, баркод, товар, потом группы. Группа сворачивается в один
сводный столбец кнопкой в шапке, как «минус» в Excel. Ноль — красная ячейка. Сумма группы
считается на сервере, чтобы страница и выгрузка показывали одно число.

Лист «Сравнение» — все кабинеты подряд, кнопка «Обновить все кабинеты».

Выгрузка — одна книга: лист на кабинет со сворачиваемыми группами столбцов (сводный слева,
`summaryRight=False`, как у неё), суммы формулами `=SUM(...)`, нули — условным форматом:
если она подвинет число руками, Excel пересчитает и перекрасит сам. Баркод записан текстом,
иначе Excel покажет 2,05E+12. Последний лист — «Сравнение».

## Расписание

Интервальное, не суточное: селлер правит кабинет днём и хочет увидеть результат в тот же
день. Кабинет собирается, если с последнего успешного сбора прошло больше `poll_minutes`
и с последней попытки — больше `retry_minutes`. Кнопка «Обновить данные» ставит запрос,
воркер забирает его в ближайший цикл; повторное нажатие возвращает тот же запрос. Запрос,
брошенный упавшим воркером, закрывается через час с ошибкой.

## Состояния и ошибки

- «Столбцы ещё не настроены» — у кабинета нет ни одной группы;
- «Впишите баркоды» — список пуст;
- «Часть баркодов не найдена в каталоге» — остаток спрошен, названия нет;
- ошибка сбора оставляет прежние остатки и их дату, текст ошибки — над таблицей;
- отключение от автоматизации сохраняет группы, баркоды и заметки; стирает их только
  удаление селлера с `purge`.

## Уведомления

Нет.

## Настройки

Секция `fbs_stocks`: `poll_minutes` — как часто опрашивать (по умолчанию 60), `retry_minutes`
— пауза после неудачи (15), `timezone`. Опрос чаще раза в 15–20 минут на пяти кабинетах
упрётся в бюджет «Маркетплейса» вместе с другими автоматизациями.
