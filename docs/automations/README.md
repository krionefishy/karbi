# Автоматизации

Автоматизация — самостоятельный модуль, который по расписанию собирает данные по
**подключённым** селлерам и что-то с ними делает. Здесь по файлу на каждую.

| Автоматизация | Что делает | Шлёт в Telegram |
| --- | --- | --- |
| [Мониторинг отзывов](WB_REVIEWS.md) | суточные срезы отзывов и рейтинга по артикулам | нет |
| [Оборачиваемость](WB_TURNOVER.md) | считает, на сколько дней хватит остатка | да, дайджест |

## Что общего у всех

**Подключение — не то же самое, что селлер.** Селлер живёт в реестре, участие в
автоматизации — отдельная запись внутри модуля. Отключение от автоматизации не удаляет ни
селлера, ни собранную историю ([business/SELLERS.md](../business/SELLERS.md)).

**Прогон покрывает подключённых и активных**, и пересечение считается заново каждый раз:
архивный селлер не должен получить задачу, потому что его ключа у нас больше нет.

**Никто не ходит в мессенджер напрямую.** Автоматизация публикует событие, называет код
бота и аудиторию; доставку берёт на себя модуль уведомлений, а наружу ходит только релей
([business/NOTIFICATIONS.md](../business/NOTIFICATIONS.md)).

**Бюджет WB общий.** Лимиты считаются на пару «категория API + токен» и делятся между
всеми автоматизациями одного селлера ([architecture/WB_API.md](../architecture/WB_API.md)).

**Своя схема в базе и свой порт подключения.** Ни одна автоматизация не читает и не чистит
таблицы другой ([architecture/MODULES.md](../architecture/MODULES.md)).
