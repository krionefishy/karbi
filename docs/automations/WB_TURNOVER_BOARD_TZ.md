# ТЗ: таблица оборачиваемости по баркодам

Расширение автоматизации «Оборачиваемость» (`wb_turnover`, сервис `wb-turnover`). Новый
сервис и новый пункт доступов не нужны: шаги 1–3 из AGENTS.md не применяются.

## 1. Зачем

Аналитик каждый день вручную сводит два отчёта кабинета WB (по заказам и по остаткам) и
считает, на сколько дней хватит товара на складе WB. Если запаса мало, она срочно включает
FBS, чтобы не было аннуляции заказов. Таблица должна делать эту сводку сама.

Образцы от заказчика: `Пример-4.xlsx` (листы «ОСНОВА» и «Пример оборачиваемости»),
выгрузка WB `supplier-goods-53172-2026-10-21-2026-10-27-*.XLSX` (Байбурин, 54 баркода).

## 2. Решения

| Вопрос | Решение |
| --- | --- |
| Единица | Баркод внутри кабинета. Ключ строки — `(кабинет, баркод)` |
| Кабинеты | Все пять: Мунаева, Саниев, Байбурин, Шелестюкова, Яночкина. Гордейчук не входит |
| Товары | Только из её списка (80 строк на старте), не весь каталог |
| Продажи | «Заказано, шт.» как в отчёте WB: заказы за 7 полных суток до вчера, сумма по всем складам и моделям (WB, FBS, зарубежные), отмены не вычитаются |
| Среднее в день | Заказов за 7 дней ÷ 7 (не ÷ дни продаж) |
| Остаток WB | «Склад WB РФ» из отчёта «Остатки на складах». Остатки на зарубежных складах не считаются (в образце 12 шт из 4207) |
| Оборачиваемость | Остаток WB ÷ среднее в день, целые дни, округление вниз. «Хватит на» и «Оборачиваемость» — один столбец |
| FBS | Признак «Есть» / «Нет» по всему кабинету, без разбивки по складам. Для артикула с несколькими баркодами — общий на артикул |
| Нет продаж | Текст «нет продаж», не число |
| Подсветка | Красный: меньше 10 дней или остаток 0 при продажах. Жёлтый: 10–19 дней. Пороги в конфиге |
| 1С | Не подключаем. «Номенклатура 1С» — её текст, хранится как введён |
| Дайджест | Telegram-дайджест не меняется: его окно 3 дня и порог 10 остаются |

## 3. Столбцы

Порядок как в «Пример оборачиваемости»:

1. Комментарии — свободный текст, правит она.
2. Кабинет.
3. Артикул WB.
4. Баркод.
5. Артикул продавца.
6. Номенклатура 1С.
7. Остатки ФБО (Склад WB РФ).
8. Продажи за 7 дней.
9. Средние продажи в день (1 знак после запятой).
10. Оборачиваемость, дн. (цвет по порогу).
11. Остатки ФБС («Есть» / «Нет»).

Артикулы и название берутся из каталога `wb_core`. Баркода нет в каталоге — строка остаётся,
артикул берётся из отчёта об остатках или из заказов, иначе пусто.

## 4. Данные

### 4.1 Заказы по баркоду

В `wb_turnover.orders` баркода нет. Нужно:

- колонка `barcode` (nullable) в таблице `orders` и индекс `(seller_id, barcode, order_date)`;
  миграция Alembic;
- `OrderRow` и разбор ответа Statistics API читают `barcode`; сбор заказов его записывает;
- разовая переподгрузка: у уже подключённых кабинетов сбросить `orders_watermark` на
  8 суток назад. Строки с тем же `srid` перезапишутся, баркод заполнится. У новых кабинетов
  стартовая подгрузка — 8 суток (`orders_backfill_days` с 3 до 8, дайджест на это не
  влияет); миграция сама сдвигает watermark на 8 суток назад;
- Statistics — запрос в минуту на ключ, общий с подсортом. Переподгрузка пяти кабинетов
  укладывается в несколько запросов.

Расчёт заказов — при чтении страницы, а не в ночном расчёте: `count(*)` по `orders` за
`[вчера − 6, вчера]` на `(seller_id, barcode)`, включая `is_cancel`. Окно задаётся
конфигом `turnover.board_window_days = 7`.

### 4.2 Остаток WB

Изменено после проверки на живых данных (28.10.2026): `quantity` отчёта
`stocks-report/wb-warehouses` по размеру (`chrtId`), слой `fbo_stocks` (миграция `wt006`),
баркод → размер через `SellerRepository.list_barcode_sizes`. Строка «Склад WB РФ» отчёта
`warehouse_remains` не годится: она есть не у всех баркодов. Остаток из зеркала не берём.

### 4.3 FBS

Слой остатков по складам продавца самой «Оборачиваемости» (`warehouse_stocks`, перезаписывается
каждым сбором), по артикулу (`barcode → article` из каталога). Сумма больше 0 — «Есть», иначе «Нет»,
слой ни разу не собирался (`tracked_sellers.fbs_stocks_at` пуст) — «—». Так не нужна зависимость
от зеркала и данные не старше слота сбора.

### 4.4 Список и комментарии

Новые таблицы в схеме `wb_turnover`:

`board_items`: `seller_id`, `barcode`, `nomenclature_1c` (text), `note` (≤ 2000), `position`,
`added_by`, `added_at`, `note_updated_by`, `note_updated_at`, `hidden_at`;
PK `(seller_id, barcode)`.

Чужие таблицы (`wb_fbs_stocks`, `wb_podsort`) не читаем.

## 5. Расчёт

```
orders7  = заказы баркода за 7 суток до вчера (с отменами, все склады)
rate     = orders7 / 7
remain   = остаток «Склад WB РФ»
days     = floor(remain / rate)       при rate > 0
статус   = no_sales                   при orders7 = 0
         = no_data                    при отсутствии снимка остатков
```

Остаток 0 при продажах — `days = 0`, красная строка. Остаток 0 и продаж 0 — «нет продаж».

## 6. API

В роутере `wb-turnover` (`/wb/turnover/board`, уже под `require_service`):

- `GET /board` — все кабинеты, строки, время последнего сбора заказов и снимка остатков,
  пометки о застарелых данных;
- `POST /board/items` — `{seller_id, barcodes: []}` пачкой; дубли и ошибки ответ перечисляет;
- `PATCH /board/items/{seller_id}/{barcode}` — комментарий, номенклатура 1С;
- `POST .../hide`, `POST .../restore`, `DELETE ...` (удаление окончательное, с подтверждением на фронте);
- `GET /board/export` — xlsx;
- `POST /board/refresh` — ставит в очередь сбор заказов (переиспользовать существующий
  механизм `refresh_requests`). Остаток WB из зеркала обновляется воркером зеркала.

Раздел доступов не меняется, существующие тесты `test_service_access.py` остаются зелёными.

## 7. Интерфейс

Вкладка «Таблица» на странице «Оборачиваемость».

- Фильтр по кабинету (плюс «Все»), поиск по баркоду / артикулу.
- Сортировка по любому числовому столбцу; по умолчанию — по оборачиваемости по возрастанию,
  «нет продаж» и «—» в конце.
- Комментарий редактируется на месте.
- Добавление: вставка списка баркодов + выбор кабинета. Скрытие / возврат / удаление строки.
- Над таблицей: «заказы собраны …», «остатки WB сняты …», пометки о застарелых данных.
- Кнопки «Обновить данные» и «Скачать Excel».

## 8. Excel

Одна книга, лист «Оборачиваемость», столбцы из п. 3. Баркод записан текстом. «Среднее» и
«Оборачиваемость» — формулы (`=H/7`, `=ЕСЛИ(H=0;"нет продаж";ОКРУГЛВНИЗ(G/I;0))`),
подсветка — условным форматом, чтобы цвета пересчитывались при правке.

## 9. Первичное наполнение

`python -m backend.commands.import_turnover_board Пример-4.xlsx` — по умолчанию пробный
прогон, `--apply` пишет. Лист «ОСНОВА»: «Кабинет» → селлер по имени, «Баркод», «Номенклатура 1С»
→ `board_items`. Остальные столбцы берутся из каталога. Отчёт команды: сколько строк
добавлено, какие баркоды не найдены в каталоге кабинета, какие кабинеты не подключены.
«Активность» из «ОСНОВА» не переносится.

Перед запуском все пять кабинетов должны быть подключены к автоматизации в админке.

## 10. Проверка

1. На образце WB (Байбурин, 21–27.10): «Заказано» по каждому из 12 баркодов кабинета и
   остаток «Склад WB РФ» совпадают с таблицей. Допуск — сутки поздних записей Statistics и
   разница во времени снимка; расхождения свыше допуска разбираем до выкатки.
2. Тесты: расчёт (нет продаж, остаток 0, нет снимка, ровное и дробное деление), сбор заказов
   с баркодом, добавление / скрытие / удаление, импорт, права (`403` без доступа), выгрузка.
3. Фронт: форматирование, подсветка, добавление списком.

## 11. Не входит

Запись в WB, перенос остатков между складами, уведомления, разбивка по складам и регионам,
автоматическое добавление строк из каталога, настройка порога в интерфейсе, остаток нашего
склада из 1С.

## 12. Риски

- Statistics дописывает заказы с опозданием: последние сутки окна могут быть чуть занижены.
- «Склад WB РФ» — агрегат WB, где именно лежит товар, не видно.
- Если заказов в «Заказано» отчёта кабинета окажется заметно больше, чем в Statistics,
  причина будет в определении отчёта; выясняем до выкатки (п. 10.1).
- Зеркало остатков обновляется раз в 6 часов; «Обновить данные» его не ускоряет.
