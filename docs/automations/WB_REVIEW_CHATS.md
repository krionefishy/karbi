# Чаты после отзыва

## Зачем

После отзыва с низкой оценкой WB сам, от имени продавца, открывает с покупателем чат:
«Здравствуйте. Вы оставили отзыв с низкой оценкой…». Этот текст продавец изменить не
может. Следом сторонняя программа по API отправляет наше сообщение; у кабинетов тексты
нарочно разные. Автоматизация отвечает на один вопрос: сколько покупателей отвечают после
нашего сообщения и сколько отвечали без него. В кабинете WB этого не посчитать — там только
список чатов.

Сообщений мы не отправляем. Автоматизация только читает.

## Что собираем

Своего сбора нет. Ленту чатов (`GET /api/v1/seller/events`, категория токена «Чат с
покупателями») читает зеркало `wb_core` — для всех активных селлеров, не только
подключённых, поэтому у только что подключённого кабинета история уже есть.

Проверено на живых кабинетах (17.09.2026):

- Автосообщение WB приходит как сообщение продавца с `source: seller-portal`. Сообщения
  менеджеров из кабинета приходят так же, поэтому отличает его только текст; сверяется
  начало фразы.
- Сообщение, отправленное программой, приходит с `source: seller-public-api`. По этому
  признаку оно и опознаётся: тексты у кабинетов разные и меняются, отчёт от них не зависит.
- Лента одна на кабинет, идёт от старых событий к новым, по 50 на страницу. Курсор `next` —
  время последнего события в миллисекундах; по нему можно начать с любой даты. На пустой
  странице WB возвращает тот же курсор.
- Карточку товара WB прикладывает только к первому сообщению нового чата. Если автосообщение
  пришло в уже существующий чат, артикула у диалога нет.
- История отдаётся как минимум за шесть недель назад; глубину первой загрузки задаёт
  `core_mirror.chats_history_days`.

Слова покупателя хранятся только в чатах, где было автосообщение WB об отзыве. По остальной
переписке (возвраты, вопросы о доставке) от покупателя остаётся факт сообщения без текста:
отчёту она не нужна, а телефонов и адресов в ней хватает. Тексты продавца хранятся всегда —
по ним историю можно переразметить, если WB сменит текст автосообщения.

## Как считаем

Чат у покупателя с продавцом один на всё время, поэтому единица отчёта — не чат, а
**диалог**: отрезок от автосообщения WB до следующего такого же в том же чате. Диалог
относится ко дню автосообщения (по Москве).

Наше сообщение — сообщение из API не позже 15 минут после автосообщения WB (на деле —
через 10–80 секунд). Сообщение из API позже этого — менеджер через сторонний клиент: в
ленте такие есть с августа, одиночные и часами позже автосообщения. Момент запуска рассылки
по кабинету — первое наше сообщение по этому правилу за всю историю. Диалоги делятся на
четыре группы:

- **С нашим сообщением** — после автосообщения WB ушло наше сообщение, и покупатель до
  него ничего не написал. Ответ ждём от нашего сообщения. Диалог с нашим сообщением всегда
  здесь, даже если его автосообщение на секунды раньше момента запуска.
- **Ответил раньше нашего сообщения** — после запуска, покупатель написал, а нашего
  сообщения не было или оно ушло уже после ответа. Программа рассылки не шлёт сообщение,
  если покупатель уже написал (проверено по ленте: ответы в таких диалогах приходят через
  30–300 секунд после автосообщения). Сюда же попадает пропуск рассылки, после которого
  покупатель всё-таки ответил. Доля ответивших здесь 100 % по построению — сравнивать её с
  группой «с нашим» нельзя.
- **Пропуск рассылки** — после запуска, нашего сообщения не было и покупатель молчит.
- **До запуска** — всё, что раньше момента запуска.

Исход диалога:

- **ответил** — покупатель написал в течение окна ответа (`review_chats.reply_window_hours`,
  48 часов) от нашего сообщения, а без него — от автосообщения WB;
- **не ответил** — окно истекло без его сообщений;
- **ждём** — окно ещё идёт.

Окно нужно потому, что чат один: без него вопрос про другой заказ через две недели
засчитался бы как ответ. «Не ответил» ставится только до момента, докуда прочитана лента:
отставший воркер не должен превращать непрочитанные ответы в молчание.

Проценты — от всех диалогов группы, «ждём» в знаменателе. Считать от диалогов с известным
исходом нельзя: в свежий день, где ещё никто не успел промолчать, девять ответов из
девятнадцати дали бы 100 %. Пока есть «ждём», доля ответивших за день может только вырасти.
Рядом с процентом всегда стоят абсолютные числа: на двадцати диалогах в день процент сам по
себе обманывает.

Честное сравнение — по времени, а не по группам внутри одного дня: **все диалоги после
запуска** за выбранный период против **всех диалогов за `baseline_days` (14) дней до дня
запуска**. Окно «до запуска» одно и то же при любом выбранном периоде. Разница показывается
в процентных пунктах; это и есть ответ на вопрос, стали ли покупатели писать реже.

Отчёт считается при чтении из событий зеркала. Правила и окно можно менять — история
пересчитается сама, пересобирать нечего.

## Что показываем

Страница `/automations/wb-review-chats`: период, три карточки — «с нашим сообщением», «все
диалоги после запуска» (со счётчиками «ответили раньше нашего» и «пропуск рассылки») и «до
запуска» с разницей в процентных пунктах; таблица по дням (все диалоги, с нашим сообщением,
два счётчика), список диалогов с фильтрами по группе и исходу и текстом ответа. Выгрузка в
Excel — сводка с днями и все диалоги периода, фильтры списка на неё не влияют.

## Расписание

Лента дочитывается зеркалом каждые `core_mirror.chats_interval_minutes` (30 минут): один
запрос на селлера, если нового нет. Первая загрузка истории идёт порциями по
`chats_pages_per_run` страниц за проход, курсор сохраняется с каждой страницей. Пока
история не дочитана до конца, страница предупреждает, что цифры неполные.

События старше `core_mirror.chats_retention_days` (180 дней) удаляются раз в сутки.

## Состояния и ошибки

- **«Лента чатов ещё не читалась»** — зеркало до кабинета не доходило; ждать до получаса.
- **«История ещё загружается»** — первая загрузка не дошла до конца ленты.
- **«Лента не читается: ключ не имеет доступа к категории „Чат с покупателями“»** — нужен
  новый ключ с этой категорией; сам не починится. Прежние события остаются на месте.
- **Диалогов нет, а в кабинете они есть** — скорее всего, WB поменял начало текста
  автосообщения. Правится константой `REVIEW_PROMPT_PREFIX` в `wb_core`; уже собранные
  события размечаются при записи, поэтому вместе с константой нужен `UPDATE` флага
  `review_prompt` по сохранённым текстам продавца. Счёт восстановится полностью; тексты
  ответов покупателей за время, пока автосообщение не узнавалось, не сохранены.
- **Наше сообщение «не уходило» после запуска рассылки** — пропуск на стороне программы
  рассылки; мы его только показываем.

## Настройки

- `review_chats.reply_window_hours` — окно ответа. Меньше — свежие дни быстрее получают
  окончательные цифры, но поздние ответы уходят в «не ответил»; больше — наоборот, и растёт
  риск засчитать разговор о другом заказе.
- `review_chats.max_period_days` — потолок периода отчёта.
- `review_chats.baseline_days` — окно «до запуска» для сравнения.
- `review_chats.follow_up_within_minutes` — не позже скольки минут после автосообщения WB сообщение из
  API считается нашим (15). Если программа рассылки начнёт задерживаться, поднять; иначе её сообщения
  уйдут в «менеджер», а диалоги — в «пропуск рассылки».
- `core_mirror.chats_*` — интервал чтения ленты, глубина первой загрузки, страниц за проход,
  срок хранения.
