# Расширения Marketplace Auto

В папке два независимых расширения Chrome с общей сборкой: возвраты WB (`src/`) и скриншоты чатов
(`screens/`). Права у них разные, поэтому это два пакета, а не одно расширение с режимами.

```bash
npm ci
npm run pack           # возвраты: dist/ и marketplace-auto-returns.zip
npm test               # тесты расширения скриншотов (vitest)
npm run pack:screens   # скриншоты: dist-screens/ и marketplace-auto-screenshots.zip
```

Установка любого из них: `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное
расширение» → папка `dist` или `dist-screens`. В образе фронта оба архива собираются сами и
раздаются по `/extension/marketplace-auto-returns.zip` и `/extension/marketplace-auto-screenshots.zip`;
адрес сервиса по умолчанию берётся из `VITE_BACKEND_URL` при сборке.

## Возвраты WB

Берёт код получения из профиля покупателя, под которым выполнен вход на wildberries.ru, и
отдаёт его бэкенду Marketplace Auto. Зачем и как устроено — в
[docs/automations/WB_RETURNS.md](../docs/automations/WB_RETURNS.md), раздел «Расширение».

Настройки: адрес сервиса и шестизначный код из бота (`/extension`) или со страницы «Возвраты WB» →
«Расширение».

Код берётся из любой открытой вкладки `www.wildberries.ru`; своя вкладка открывается, только если
такой нет. Антидетект-браузеры (Dolphin) запрещают расширению открывать вкладки — там вкладку
wildberries.ru держит открытой менеджер, а после ошибки расширение пробует снова каждые 10 минут.

Раз в три часа расширение перезагружает фоновую вкладку wildberries.ru: сайт при загрузке продлевает
токен сессии, и она не протухает от бездействия. Активную вкладку менеджера оно не трогает.

## Скриншоты чатов («Контроль скриншотов ДБС»)

Менеджер открывает чат с покупателем в кабинете WB, жмёт иконку или Alt+Shift+S, выбирает исход
«Полож / Доп / Удален» — снимок видимой части вкладки уходит на сервис вместе с исходом.

- **Права:** `activeTab`, `storage`, `alarms`. Ни `tabs`, ни `scripting`, ни контент-скриптов, ни
  постоянного доступа к wildberries.ru: снимок и адрес вкладки Chrome даёт только по жесту
  (клик по иконке или горячая клавиша). Доступ к адресу сервиса запрашивается при подключении.
- **Подключение:** в настройках адрес сервиса и код из 8 символов со страницы «Контроль
  скриншотов» → «Расширение» (Crockford base32: O читается как 0, I и L как 1). Токен `mas_…`
  привязан к установке (`install_id` в `chrome.storage.local`); повторное подключение отзывает
  прежний. Попыток ввода на сервере 10 за 10 минут, дальше 429.
- **Адрес:** отправить можно только с адресов из `allowed_url_prefixes` (по умолчанию
  `https://seller.wildberries.ru/chat-with-clients`), список приходит с сервера при подключении и
  в `/me`.
- **Метаданные:** `client_url` (адрес вкладки), `client_captured_at`, `tz_offset_min` (как
  `Date.getTimezoneOffset()`, для Москвы −180), размеры вкладки и `devicePixelRatio`, версия в
  `X-Extension-Version`. Времени клиента сервер не верит.
- **Очередь:** IndexedDB, одна запись на захват, `client_submission_id` = id захвата, поэтому
  повтор безопасен. Попап кладёт снимок в базу и передаёт service worker'у только сигнал
  «отправь», blob через `runtime.sendMessage` не ходит. Повторы: 1 мин, 5 мин, 15 мин, 1 ч, дальше
  раз в час, не дольше 72 ч — потом «не отправлено», запись ждёт ручного решения в настройках.
  Прочие 4xx (413/415/422…) не повторяются: запись удаляется, причина видна в попапе.
  401 стирает токен и ставит очередь на паузу (красный «!» на иконке), 403 и 426 — пауза;
  429 — ждём `Retry-After`. Снимок больше 6 МБ перекодируется в JPEG q=0.92.
- **Код:** `screens/src/` — `popup.ts` (захват, исход, опрос статуса), `background.ts` (очередь,
  будильники, бейдж), `queue.ts`, `api.ts`, `capture.ts`, `settings.ts`, `options.ts`;
  сборка — `vite.screens.config.ts`, тесты — `screens/test/`.
